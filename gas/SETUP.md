# 結帳串接 Google 試算表：設定步驟

整體流程：

```
網站結帳 ──POST(JSON)──▶ Apps Script 網頁應用程式 ──▶ 試算表
                         ├ 驗證資料、以「網站商品」表重算金額
                         ├ 寫入「網站訂單」「網站訂單明細」
                         ├ 產生編號 GC261128-001（每天重新編號）
                         └ 寄通知信給店家
```

## 一次性設定（約 10 分鐘）

1. **建立試算表**：到 Google 試算表新增一份空白試算表，命名例如「金脆鍋貼訂單」。
2. **貼上程式**：試算表選單 **擴充功能 → Apps Script**。
   - 把 `Code.gs` 的內容整份貼進編輯器（取代預設的 `myFunction`）。
   - （選用）左側 ⚙ 專案設定 → 勾選「在編輯器中顯示 appsscript.json」，貼入 `appsscript.json` 內容，確保時區為 `Asia/Taipei`。
3. **初始化**：上方函式選單選 `setup` → 按 **執行**，依畫面授權（會要求存取試算表、寄信、觸發器）。
   - 會自動建立 4 個工作表：**網站訂單**、**網站訂單明細**、**網站商品**（已填入網站 15 個品項與價格）、**網站設定**。
   - 名稱都加了「網站」前綴，不會動到你試算表裡原本的「訂單」「商品」等工作表。若同名工作表已存在且內容不同，`setup` 會直接停下並說明，不會覆蓋。
   - 並建立每天 22:30 寄送「當日彙總」的定時觸發器。
4. **部署成網頁應用程式**：右上 **部署 → 新增部署作業 → 類型選「網頁應用程式」**
   - 執行身分：**我**
   - 誰可以存取：**所有人**
   - 按部署，複製 **網頁應用程式網址**（`https://script.google.com/macros/s/…/exec`）。
5. **貼回網站**：打開 `index.html`，找到
   ```js
   const ORDER_API = '';
   ```
   貼上網址後 commit / 合併。尚未填寫時，網站維持「示範模式」（不會寫入試算表）。
6. **測試**：
   - 瀏覽器開啟 `網址?action=ping`，看到 `{"ok":true,...}` 代表部署成功。
   - 試算表選單 **🥟 金脆鍋貼 → 寫入一筆測試訂單**，確認「網站訂單」表出現資料並收到通知信。
   - 在網站實際下一筆單。

> ⚠️ 之後**修改 Code.gs** 要重新部署才會生效：部署 → **管理部署作業** → ✏️ 編輯 → 版本選「新版本」→ 部署（網址不變）。

## 日常使用

| 想做的事 | 作法 |
| --- | --- |
| 看新訂單 | 開「網站訂單」表；新單狀態為「待確認」（黃底） |
| 更新進度 | 直接改「狀態」下拉：待確認 / 製作中 / 可取餐 / 已完成 / 已取消（整列會變色） |
| 暫停接單（打烊、賣完） | 「網站設定」表 `ACCEPT_ORDERS` 改 `FALSE`；顧客送單時會看到暫停接單訊息 |
| 改通知信箱 | 「網站設定」表 `NOTIFY_EMAIL`（可用逗號分隔多個；留空＝寄給部署者） |
| 品項停售 | 「網站商品」表取消勾選「上架」，該品項無法下單 |
| 調整價格 | 「網站商品」表改單價 **並同步修改 `index.html` 的價格**。系統以「網站商品」表的價格為準，兩邊不一致時會在「系統備註」標示「金額不符」 |
| 新增品項 | `index.html` 加品項，同時在「網站商品」表新增同樣的「品項ID」 |

## 防護機制

- **金額以試算表為準**：不信任瀏覽器送來的價格，避免被竄改。
- **重複送出保護**：同一次結帳共用 `requestId`，網路逾時後再按一次不會重複下單。
- **頻率限制**：同一支手機 10 分鐘內最多 5 筆。
- **機器人陷阱**：隱藏欄位 `website` 有值就直接丟棄。
- **公式注入防護**：姓名／備註等以 `= + - @` 開頭時自動補單引號。
- **上鎖**：同時下單時用 `LockService` 排隊，避免編號重複。

## 限制與提醒

- 網址公開，任何人都能送單；以上防護可擋掉大多數濫用，但不等於完整防刺探。若遇到大量垃圾單，可考慮加入 reCAPTCHA。
- 一般 Google 帳號寄信額度約每天 100 封，超過時訂單仍會寫入，只是不寄通知。
- Apps Script 回應約 1–3 秒，網站按鈕會顯示「送出中…」。
- 目前**沒有線上付款**，訂單為「待確認」後由店家聯絡顧客。
- 試算表內含顧客姓名、手機、地址，請只分享給需要的店員，並注意個資保護。

## 疑難排解

| 狀況 | 原因與處理 |
| --- | --- |
| `儲存格 M3 設有資料驗證規則…待處理, 製作中…` | 試算表原本就有同名工作表（舊版程式用了「訂單」），舊的資料驗證擋住寫入。更新到最新版 `Code.gs`（名稱改為「網站訂單」等）後重新執行 `setup`。 |
| `已有名為「…」的工作表，且內容與本系統不同` | 新名稱也撞到你自己的工作表。把那個工作表改名，或刪除後再執行 `setup`。 |
| 舊版 `setup` 已經動到原有工作表 | 在試算表選 **檔案 → 版本記錄 → 查看版本記錄**，還原到執行前的版本，或只複製回被改動的標題列／格式。 |
| 修改程式後網站沒變化 | 要重新部署：部署 → 管理部署作業 → ✏️ → 新版本 → 部署。 |
| 網站顯示「網路連線異常」 | 確認部署時「誰可以存取」選的是「所有人」，且 `ORDER_API` 貼的是 `/exec` 結尾的網址（不是 `/dev`）。 |
